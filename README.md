# 데이터 분석 (웹)

파일에 들어 있는 계측 데이터를 불러와 그래프를 그리고 기간 통계를 내는 도구다.
서버 없이 브라우저 안에서만 동작한다. 데이터는 어디로도 전송되지 않는다.

같은 기능을 iOS 앱으로 옮기기 전에 판별 로직과 성능을 검증하려고 만들었다.

## 지금 되는 것

- **파일 불러오기** — CSV · TSV · TXT · XLSX · JSON, 여러 개 동시에
- **자동 판별** — 인코딩(UTF-8 / CP949), 구분자, 헤더 유무, 시간축 유무, 샘플레이트, 중복·결측 구간
- **채널 등록** — 컬럼 중 쓸 것만 골라 담아두고 모든 화면에서 공유
- **시계열** — 여러 채널 겹쳐보기, 공통 축 / 개별 축(정규화)
- **상관** — X축을 시간이 아닌 다른 채널로 (온도 상관 등), 회귀선과 상관계수, 시간 순 색상
- **기간** — 세 화면이 공유하는 구간 선택. 시각 입력 또는 그래프를 끌어서
- **관리기준선** — 그래프마다 최대 4개, 일회성. 위험/주의/기준/보조 색
- **신호처리** — Zero correction(평균·첫값·추세 제거), 영위상 버터워스 LPF/HPF/대역, FFT
- **케이블 장력** — 진동법(현이론). 배음 열로 1차 진동수를 추정하고 결과를 표로 모아 내보내기
- **분석** — 시간 / 일 / 주 / 월 / 연 단위 집계 통계 표, CSV 내보내기
- **내보내기** — 그래프 PNG(라이트 고정, 2배 해상도), 집계표 CSV(엑셀용 BOM 포함)

### FFT에 대해

- 윈도우 크기 1024 / 2048 / 4096 / 8192 / 16384
- 창함수 Hann · Hamming · 사각 · Flat-top
- 겹쳐 평균(Welch, 50% 중첩)으로 잡음을 줄인다
- 봉우리는 로그 영역 포물선 보간으로 주파수와 진폭을 함께 보정한다.
  합성 신호로 검증한 진폭 오차는 Flat-top 0.1%, Hann 2.5%.
  **진폭 값 자체가 중요하면 Flat-top을 쓴다**
- 필터는 앞뒤로 두 번 걸어 위상 지연이 없다(영위상). 대신 실효 차수가 4차가 되고
  차단주파수에서 −3 dB가 아니라 −6 dB다
- 등간격 시간축이 아닌 채널은 아예 고를 수 없게 막는다

### 케이블 장력에 대해

두 가지를 함께 낸다. 차수별로 `T = 4mL²(fn/n)²` 를 구한 뒤

- **Single Mode** — `(fn/n)²` 의 평균 × `4mL²`
- **Multi-Mode** — `(fn/n)²` 를 `n²` 에 회귀한 **y절편** × `4mL²`.
  회귀 **기울기**에서 휨강성 `EI = 기울기 × 4mL⁴/π²` 도 함께 나온다

단위는 `m [ton/m]`, `L [m]`, `fn [Hz]` → `T [kN]`. 입력은 ton/m · kg/m · kN/m 중에 고른다
(kN/m 은 단위중량이므로 9.80665로 나눠 단위질량으로 바꾼다).

**쓸 차수는 사람이 고른다.** 자동으로 배정해 채워두지만 그래프를 보고 켜고 끌 수 있고,
주파수를 직접 입력해도 된다. 자동에 맡기면 안 되는 이유가 있다 — 실제 데이터에서
검출 봉우리 수를 12개에서 20개로 늘렸더니 추정 f₁ 이 1.423 Hz 에서 0.476 Hz 로 바뀌었다.
**장력으로는 9배 차이다.** 어느 쪽이 맞는지는 봉우리들이 등간격으로 늘어서는지를
사람이 봐야 판단할 수 있다.

휨강성이 음수로 나오거나 상관계수가 낮으면 화면에 경고를 띄운다.
회귀가 데이터에 맞지 않는다는 뜻이므로 쓰는 차수를 조정해야 한다.

보고서는 브라우저 인쇄로 PDF를 만든다. 케이블 한 가닥에 한 쪽이고,
Cable Properties · 차수별 표 · y절편 · 기울기 · 상관계수 · 휨강성 ·
Single/Multi-Mode 장력(kN, tonf) · 스펙트럼 · 회귀 그래프가 모두 들어간다.
그림은 **결과를 담는 시점에 저장**한다. 채널을 바꾼 뒤에는 다시 그릴 수 없기 때문이다.

정확도를 가르는 것은 FFT 정밀도가 아니라 **차수 판별**이다.
2차를 1차로 잘못 집으면 장력이 4배로 틀린다. 그래서 최대 봉우리를 쓰지 않고
봉우리들이 f1의 정수배로 늘어서는지를 본다. 채점에서 조심한 것들:

- 차수 하나에 봉우리 하나만 센다 (잡음 봉우리 넷이 모두 "1차"가 되는 걸 막는다)
- 가장 긴 **연속** 차수 구간으로 점수를 낸다 (동떨어진 잡음 차수가 정답을 짓누르는 걸 막는다)
- f1의 정수배를 다시 채점해 부조화(장력이 1/4로 나오는 오류)를 거른다

차수를 정한 뒤에는 그 차수들로 f₁을 **최소제곱으로 다시 맞춘다**. 봉우리 하나를
차수로 나눈 값보다 정확하고, 높은 차수일수록 무게가 실린다.

합성 신호 33회 시험에서 1차가 아예 없어도 배음 간격만으로 f₁을 되찾았다(최대 오차 2.4%).
1·2차가 모두 없고 봉우리가 셋뿐이면 원리상 모호하므로, 그럴 때는 화면에
역산했다고 표시하고 차수 표를 보여준다. **결과는 항상 차수 표로 확인하고,
필요하면 1차 진동수를 직접 지정한다.**

## 파일 구조

`index.html`이 아래 순서대로 불러온다. **순서가 바뀌면 깨진다.**

| 파일 | 역할 |
| --- | --- |
| `js/core.js` | 색 팔레트, DOM 도우미, 테마, 숫자·시간 포맷, 파일 내려받기 |
| `js/parse.js` | 1층 — 파일을 테이블로. 인코딩·구분자·헤더·시간축 판별 |
| `js/store.js` | 2층 — 채널 저장소와 화면 설정 |
| `js/plot.js` | 캔버스 공통 — LTTB 다운샘플링, 눈금, 축, PNG 저장 |
| `js/ts.js` | 시계열 화면 |
| `js/xy.js` | 상관 화면 |
| `js/agg.js` | 분석 화면 (기간 집계) |
| `js/ui.js` | 파일·채널 목록, 공용 채널 선택 필드 |
| `js/app.js` | 진입점 — 파일 불러오기와 이벤트 연결 |

외부 의존성은 XLSX 파싱용 [SheetJS](https://sheetjs.com) 하나뿐이고 CDN에서 가져온다.

## 설계 원칙

**3층 구조.** 파일 → 테이블 → 채널 → 분석 화면. 화면은 채널 저장소에서만 데이터를 꺼낸다.
화면을 갈아엎어도 파서와 판별 로직은 그대로 남는다.

**판별은 자동, 수정은 수동.** 인코딩이든 샘플레이트든 자동으로 정하되 결과를 항상 화면에 드러내고
사용자가 고칠 수 있게 둔다. 조용히 틀리는 것이 가장 나쁘다.

**할 수 없는 것은 막고 이유를 말한다.** 시간축이 불규칙한 채널에는 FFT·필터 버튼을 잠근다.
결측이 있는 데이터에 주파수 해석을 하면 결과가 그럴듯하지만 틀린다.

**출력물은 테마와 무관하게 라이트 고정.** 다크 모드에서 저장해도 흰 배경 PNG가 나온다.

## 실제 데이터에서 확인한 것

만들면서 실제 파일로 검증한 내용이다. 파서가 이걸 처리한다.

- 계측기 CSV가 **CP949**로 저장되어 나오는 경우가 있다. UTF-8로만 읽으면 한글 컬럼명이 깨진다
- **시간 컬럼이 아예 없는** 파일이 있다. 이때는 샘플레이트를 손으로 넣어야 한다
- 1년치 10분 통계에 **타임스탬프 중복**(내용까지 같은 행)과 **결측 구간**이 섞여 있다.
  중복을 그대로 그리면 세로선이 생기고, 결측을 직선으로 이으면 없는 데이터가 있는 것처럼 보인다
- 원시 데이터는 100 Hz가 많지만 10 Hz, 20 Hz도 있다. 고정하지 말고 추정해야 한다
- 한글 헤더 CSV는 **BOM 없이 내보내면 엑셀에서 깨진다**

## 성능

6만 행 × 여러 컬럼까지는 브라우저에서 무리 없다.
계산은 항상 원본으로 하고, **화면에 그릴 때만** LTTB로 2,000점 정도까지 줄인다.
이 분리를 지키지 않으면 스크롤이 끊긴다.
